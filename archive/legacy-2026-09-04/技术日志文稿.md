## 一、背景与定位

有两个独立系统，本日志记录它们如何融合成「一个账本、两个入口」：

| 系统 | 形态 | 角色 | 位置 |
|---|---|---|---|
| **expense-portable** | 终端 Python 脚本 + 本地 MLX 模型 | **采集端**：中文口语 → 结构化记账 JSON | `/Users/zhengwang/github_repos/expense-portable/`（GitHub 仓库，本文件夹不收录） |
| **打工人小账本工作台** | 单文件 HTML，部署在 WorkBuddy 资料库 | **呈现端**：云端存储 + 可视化 + 跨设备同步 | 本文件夹 `worker_ledger.html`（本地副本） |

**融合定位**：模型只负责「口语 → 结构化」这一件事，工作台负责「存储 + 可视化 + 同步」。两者通过「本地桥接服务」和「云端数据表」两条通道连接。

**本地模型**：oMLX 运行 `Qwen3.5-4B-expense-MLX-4bit`（LoRA 微调），OpenAI 兼容接口 `http://127.0.0.1:8000`。核心函数 `omlx_expense_bridge.bookkeep(text)` 把口语解析成 JSON：

```json
{"action":"add","amount":25,"category":"餐饮","description":"咖啡","date":"2026-08-31","payment":"微信"}
```

模型输出 **19 类分类**，工作台只认 **6 类**（吃饭/交通/购物/娱乐/房租/其他），中间有降维映射（见第六节）。

两条通道：

## 六、核心技术要点与坑（可复用）

### 1. 分类降维映射（模型 19 类 → 工作台 6 类）

```
餐饮 → 吃饭
交通 → 交通
购物 → 购物
娱乐 → 娱乐
房租/水电、房租、居住 → 房租
其余 → 其他
「收入」类 → 拦截，不进支出流水，提示走月度总结
```

注意：工作台 AI 面板里的 `mapAiCategory` 与 `cloud_sync.py` 里的 `CATEGORY_MAP` 是两处独立实现，**必须保持一致**。改一处要同步改另一处。

### 2. 真实时薪公式（与 worker_ledger.html 的 `calculateHourlyProfile` 逐行对齐）

```
月计薪天数 = 21.75 天
annual_income = 到手月薪 × 发薪月数
net = annual_income − 每月工作成本 × 12
invested = (每天在场小时 × 21.75 + 单程通勤分钟 × 2 × 21.75 / 60 + 每周加班小时 × 52 / 12) × 12
realHourly = net / invested   （invested ≤ 0 时 = 0）
换算工时 = 金额 / realHourly   （realHourly = 0 时 = 0）
```

实测样例（月薪 13800 / 13 薪 / 成本 850 / 在场 9h / 通勤 48min / 加班 6h）→ 真实时薪 **¥54.96**。

### 3. HTTPS 页面 → 本地 localhost 的三重拦截

浏览器从 `workbuddy.cn`（HTTPS）页面直连本地 `127.0.0.1:8899` 会撞三道墙：

1. **Mixed Content**：HTTPS 页里发 HTTP 请求被拦。
2. **CORS**：跨源，需要 `Access-Control-Allow-Origin: *`。
3. **Private Network Access (PNA)**：公网站点访问本地网络，Chrome 需要返回 `Access-Control-Allow-Private-Network: true`。

桥接服务必须三样齐备，否则 `fetch` 直接失败。Safari 对 PNA 支持较晚；手机跨设备仍访问不到 Mac 本地（需同局域网暴露）。

### 4. DSDK002 lint 坑（资料库 SDK）

资料库 SDK 调用时，`databaseId` **必须是字符串字面量，不能是变量**（`databaseId: dbid` 会报 DSDK002 错误）。

解法：封装函数里用「三分支字面量」——每个 `db.query/addRecord/updateRecord/deleteRecord` 调用括号内，直接写死三张表 ID 之一。

### 5. PropertyValue 写入格式

资料库写库时，字段值用 oneof 包装：

| 字段类型 | 写入格式 | 查询返回 |
|---|---|---|
| currency | `{"currency": 1234.56}`（number） | number |
| number | `{"number": 9}` | number |
| select | `{"select": "吃饭"}`（文本或选项 id） | 选项文本 |
| text | `{"text": "咖啡"}` | 字符串 |
| date | `{"date": "2026-06-24"}`（ISO 8601） | ISO 8601 带时间，前端用 `slice(0,10)` 取日期 |

### 6. 资料库写库 token 协议

云端写入需 open platform token，只能由 WorkBuddy agent 经 `connect_open_platform` 获取，**终端进程拿不到**。这是阶段 1 采用「本地队列 + flush 两段式」的根本原因。

库脚本子进程协议：token 占 stdin 首行（脚本用 `readline` 读），业务 payload 走第二行：

```bash
printf '%s\n%s' "$TOKEN" '{"database_id":"...","records":[...]}' | python3 batch_add_database_records.py --token-stdin --stdin
```

坑：脚本出错时输出 `{"error":...}` 但 **exit code 仍是 0**，需解析 stdout 判断成败，不能只看退出码。

### 7. 分类重复归一化坑

`cloud_sync.py` 的 `enqueue` 阶段已经把「餐饮」归一成「吃饭」；`flush` 阶段若再调用一次 `normalize_category`，会把「吃饭」（非 19 类 key）误降成「其他」。

修法：`flush` 里先做 `VALID_CATEGORIES` 白名单 pass-through，只对未命中的原始值做归一化。

### 8. 模型离线判定

`bookkeep` 调用失败时内部 catch 返回**空数组**，无法区分「模型离线」和「没听懂」。

修法：桥接层在返回空数组时，再探一次 `/v1/models`，若离线则返回明确错误「本地模型离线，请先打开 oMLX 加载微调模型」。

## 七、使用方式

### 终端记账（采集端）

```bash
cd /Users/zhengwang/github_repos/expense-portable
python3 omlx_expense_bridge.py "今天买咖啡花了25，微信支付"
# 末尾会提示「已入队 N 笔到云端待同步」
```

### 同步到云端（呈现端）

在 WorkBuddy 里说一句 **「同步账本」**，agent 会取 token 把本地队列 flush 进云端流水表，手机打开工作台即见。也可挂每日定时自动化静默刷。

### 网页端 AI 记账（阶段 0 入口）

1. Mac 上双击 `启动AI记账桥接.command`（先确保 oMLX 已加载微调模型）。
2. 浏览器打开工作台链接，在 AI 记账面板输入口语 → 解析 → 预览确认 → 写云端。
